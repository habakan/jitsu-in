# モジュールの規約

<sup>[English](../module-abi.md)</sup>

このリポジトリの2つの WebAssembly モジュールは、呼び出し規約を共有しています。
ホストが依存できる性質と共通ルールをこのページにまとめ、個別の export や構造体は各モジュールの ABI 文書で説明します。

## モジュールが保証すること

各項目は右欄の検査で CI 上確認しています。他のモジュールを確認するときにも、この表をチェックリストとして使えます。

| | 意味 | 検査 |
|---|---|---|
| **import が 0 個** | モジュールから外部関数を呼べません。時計、ファイルシステム、ネットワーク、確保器もありません。ホスト関数を渡さずに `instantiate(bytes, {})` で実行できます | `make check-wasm` |
| **線形メモリが伸びない** | 最大値を最小値と等しく宣言しているため、不正な入力でホストのメモリを使い切ることはありません | `make check-wasm` |
| **可変グローバルを export しない** | ホストは呼び出しの合間にモジュールの内部状態を書き換えられません | `make check-wasm` |
| **機能集合が固定されている** | [Lime1](https://github.com/WebAssembly/tool-conventions/blob/main/Lime.md)（WebAssembly 1.0 と標準化済みの5機能）で検証します。制約のあるランタイムで動作し、要求する機能も増えません | `make check-wasm` |
| **返答の配置が固定** | 既知のオフセットに構造体を返します。フィールド位置は assert で確認しており、ホストが直列化形式を解析する必要はありません | `make check-layout` |
| **バイトが同じハッシュに再現する** | バージョンを固定したツールチェーンでビルドすると、[checksums.txt](../../checksums.txt) に記載したハッシュになります。ホストは読み込んだモジュールをこのソースに結び付けられます | `make check-repro` |
| **独立したホストが一致する** | 別々に書いた3つのホストライブラリが、同じ入力に対してバイト単位で同じ出力を出すことを確認します | `make check-hosts-agree` |
| **外部のオラクルが一致する** | 解析器の結果を、同じ作者の第2実装ではなく Bitcoin Core と照合します | `make check-core-diff` |

最初の4項目は `.wasm` ファイルから直接確認できます。残りの4項目は、ビルドまたはリポジトリ内の検査が必要です。
