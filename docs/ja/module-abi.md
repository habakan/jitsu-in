# モジュールの規約

<sup>[English](../module-abi.md)</sup>

このリポジトリの2つの WebAssembly モジュールは、呼び出し規約を共有しています。
ホストが依存できる性質と共通ルールをこのページにまとめ、個別の export や構造体は各モジュールの ABI 文書で説明します。

## モジュールが保証すること

各項目は右欄の検査で CI 上確認しています。他のモジュールを確認するときにも、この表をチェックリストとして使えます。

| | 意味 | 検査 |
|---|---|---|
| **import が 0 個** | モジュールは外を呼べない。時計もファイルシステムもネットワークも確保器も無い。渡すホスト関数が無いので `instantiate(bytes, {})` が全てになる | `make check-wasm` |
| **線形メモリが伸びない** | 最大値を最小値と等しく宣言しているので、不正な入力でホストのメモリを食い潰せない | `make check-wasm` |
| **可変グローバルを export しない** | ホストが呼び出しの合間に内部状態を書き換えられない | `make check-wasm` |
| **機能集合が固定されている** | [Lime1](https://github.com/WebAssembly/tool-conventions/blob/main/Lime.md)（WebAssembly 1.0 と標準化済みの5機能）で検証が通る。制約のあるランタイムで動き、黙って要求が広がることもない | `make check-wasm` |
| **返答の配置が固定** | 返ってくるのは既知のオフセットにある構造体で、フィールド位置は assert されている。ホストが解析する直列化形式ではない | `make check-layout` |
| **バイトが同じハッシュに再現する** | 版を固定したツールチェーンでビルドすると [checksums.txt](../../checksums.txt) のハッシュになる。ホストが読み込んだモジュールをこのソースに結び付けられる | `make check-repro` |
| **独立したホストが一致する** | 別々に書かれた3つのホストライブラリが、同じ入力に対してバイト単位で同じ出力を出すことを要求する | `make check-hosts-agree` |
| **外部のオラクルが一致する** | 解析器の答えは、同じ作者による第2実装ではなく Bitcoin Core と突き合わせる | `make check-core-diff` |

最初の4項目は `.wasm` ファイルから直接確認できます。残りの4項目は、ビルドまたはリポジトリ内の検査が必要です。
